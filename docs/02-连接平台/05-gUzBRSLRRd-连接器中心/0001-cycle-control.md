# 介绍

## **流程暂停**

在流程设计中，你可能需要临时中断流程的执行，并在之后某个合适的时间点再次启动流程。为此，我们提供了**流程暂停**功能，它允许你暂停并在之后恢复流程的运行。这样，就可以灵活地处理那些需要较长时间完成的业务操作。

### **能力说明**

**流程暂停**功能赋予了节点流程可暂停及恢复执行的能力。用户可以按照业务需求，在流程的特定节点处将其暂停，并选择在合适的时间或收到特定回调后继续执行流程。接下来，我们将介绍**流程暂停**的执行动作：

#### **延时执行**

当流程执行到当前节点时暂停运行，在某个特定时间点或固定延时时间后，恢复运行。支持两种延时类型：

| **类型** | **描述** |
| --- | --- |
| 固定时间 | 设置一个延时时长T，当流程暂停T时刻后自动恢复运行。  **[!NOTE]**  T最大支持31天，支持以 秒/分钟/小时/天 为单位。 |
| 指定时间 | 设置一个固定日期，到达该日期时自动恢复运行。  **[!NOTE]**  日期需要在31天内。 |

#### **从当前节点暂停**

当流程执行到当前节点时暂停运行，可按照提供的流程恢复方式来恢复流程运行。

#### **恢复方式**

目前支持使用 webhook 回调的方式来恢复流程运行。回调 URL 可在流程的执行记录中获取。

> **[!NOTE]**
>
> 回调 URL 说明：
>
> - URL格式：https://connector.dingtalk.com/task/resume?taskId={taskId}
> - URL特征：每次触发流，都会新的唯一 taskId。

## **流程变量**

在编排流程的过程中，你可能需要对特定流程节点的输入参数和输出参数进行操作，或者你需要定义一个临时变量以便于后续的操作。**流程变量**功能为你提供了这种灵活且便捷的处理能力。你可以根据具体业务需求，创建所需的流程变量，并在之后的流程中使用或更新定义的变量。

### **能力说明**

**流程变量**提供了创建基本类型变量、更新基本类型变量、创建对象类型变量和更新对象类型变量执行动作。

> **[!NOTE]**
>
> 流程变量具有限定的使用范围，即它们的作用域是局部的：
>
> - 如果流程变量是在主流程中创建的，那么它可以被主流程中后续的所有节点所使用。
> - 如果流程变量是在一个分支内创建的，那么它仅能在该分支内被使用。
> - 如果流程变量是在循环结构中创建的，那么它只能在当前的这个循环中使用。

#### **创建基本类型变量**

创建基本类型的变量，预设在流程中使用的值。

##### **入参配置**

| **配置项** | **类型** | **必填** | **描述** |
| --- | --- | --- | --- |
| **变量组** | Array | — | 变量组中可创建多个变量，可通过单击**新增变量**向变量组添加新的变量。 |
| **变量key** | String | 是 | 变量编码，不能与其他变量同名，保证编码唯一。 |
| **变量名称** | String | 否 | 变量名称，后置节点中显示该名称。不输入则默认为变量编码。 |
| **变量类型** | String/Number/Boolean | 否 | 变量类型，默认为String类型。 |
| **默认值** | String/Number/Boolean | 是 | 变量的默认值。 |

##### **出参配置**

| **配置项** | **类型** | **描述** |
| --- | --- | --- |
| **变量组** | Object | 出参为所有变量的键值对。 |
| **变量key** | String/Number/Boolean | 创建时设置的变量值。 |

#### **更新基本类型变量**

更新基本类型的变量，后置流程节点将获取到更新后的值。

#### **创建对象类型变量**

创建Object类型的变量，变量各字段可引用前置节点的出参值，或自定义输入值。后置节点可以获取该变量的任意字段值。

##### **入参配置**

| **配置项** | **类型** | **必填** | **描述** |
| --- | --- | --- | --- |
| **变量key** | String | 是 | 变量编码，不能与其他变量同名，保证编码唯一。 |
| **变量名称** | String | 否 | 变量名称，后置节点中显示该名称。不输入则默认为变量编码。 |
| **变量初始值** | Object | 是 | Object类型变量，通过单击**设置变量结构**按钮，进行自定义设置。 |

##### **出参配置**

| 配置项 | 类型 | 描述 |
| --- | --- | --- |
| 变量值 | Object | 变量结构与入参中设置的结构一致，在后置节点可以引用该变量任意字段的值。 |

#### **更新对象类型变量**

更新Object类型的变量，后置流程节点将获取到更新后的值。

> **[!NOTE]**
>
> 在使用**数据存储**内置工具前，首先要在当前流程所属的**连接项目**下，创建一个**数据存储项**。

## **字段值映射**

在流程设计过程中，你可能需要将流程中的字段值转换成特定格式的数据。举个例子，当A系统与B系统进行数据集成，A系统中的城市字段为“杭州”，而B系统中则使用“杭州市”。为了实现数据集成，您需要将“A系统”的城市名称映射转换为“B系统”的对应格式，即“杭州”映射为“杭州市”。字段值映射功能正是用于支持此类转换，它使得流程中的字段适配变得简单快捷。

### **功能说明**

**字段值映射**具有一个执行动作**通过查询映射表配置映射规则**。该执行动作在进行映射时，需要预先配置映射表，映射表均为Map键值对格式。具体格式如下：

```
{
  "香蕉": "Apple",
  "苹果": "Banana",
  "梨子": "Pear"
}
```

映射表有3种来源：

- 录入映射表：自行在执行动作配置时录入即可。
- 引用变量：引用上文节点返回的键值对类型变量。
- 数据映射表：该数据源需要配合连接项目使用。可在配置中心 > 连接项目 > 数据存储中，配置当前项目所属的键值对映射数据。

## **FaaS 脚本**

当需要处理前置节点生成的复杂数据时，可通过FaaS脚本实现自定义业务逻辑并输出结果。

该功能适用于在流程中嵌入灵活的数据处理能力，支持JavaScript和Python语言，满足多样化的业务场景需求。

### **能力说明**

FaaS（Function as a Service）脚本是钉钉流程自动化中的高级能力，允许开发者在流程节点中运行自定义代码，完成数据转换、条件判断、聚合计算等复杂逻辑处理。

脚本执行上下文包含以下关键元素：

- `event`：接收来自前置节点的输入数据，格式为JSON对象。
- `callback`：用于返回处理结果，必须调用以传递数据至下一节点。
- 支持异步操作（需在超时时间内完成）。

目前提供两种运行环境供选择：

- **Node.js**：基于V8引擎，支持ES6+语法，适合轻量级数据处理。
- **Python**：支持标准Python 3语法，便于进行数学运算或调用内置库。

> 注意：脚本仅支持同步返回结果，不支持长期后台任务或外部网络请求。

### **使用指引**

#### **执行限制**

| **项目** | **限制** |
| --- | --- |
| 超时时间 | 5秒（超过将被强制终止） |
| 内存限制 | 128MB |
| 代码大小 | 不超过5KB |
| 支持语法 | JavaScript（Node.js）、Python 3基础语法 |
| 禁止行为 | 网络请求、文件系统访问、进程调用 |

#### **权限角色要求**

- 必须具备“应用开发管理员”权限才能配置和保存脚本。
- 普通成员仅可触发流程执行，无法查看或修改脚本内容。

#### **上下文变量说明**

- `event`：传入的输入参数，来源于前一个节点的输出数据。

  - `error`：错误信息，无错误时设为`null`。
  - `result`：输出数据，将作为下一个节点的输入。

## **循环控制**

在你的流程操作中，如果引入了循环节点去处理特定业务逻辑，并且希望在循环过程中能够在满足特定条件时提前结束整个循环或跳过当前的循环迭代，你可以借助**循环控制**工具来实施精确的循环操作控制。

### **能力说明**

循环控制包含**终止循环**和**跳出循环**两个执行动作。

- 终止循环：立即结束本次循环，并终止后续循环。其作用同循环控制语句 break。
- 跳出循环：立即结束本次循环，并继续后续循环。其作用同循环控制语句 continue。

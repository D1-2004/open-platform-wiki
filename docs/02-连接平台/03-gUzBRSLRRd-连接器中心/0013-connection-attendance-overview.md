# 概述

## **简介**

钉钉考勤可随时随地了解团队状态，**出勤人员一目了然**；**智能统计考勤数据**，一键下载，无需人工核算；云端存储，**考勤数据永不丢失**。更多介绍请参见[钉钉使用手册-考勤](https://alidocs.dingtalk.com/i/p/Y7kmbokZp3pgGLq2/docs/3KLw95QMzkb8gRGgMK6oJAjrymPeEN2q)。

## 场景说明

考勤共有3个触发事件和4 个执行动作，支持对**员工打卡**、**排班变更**、**员工加班**事件的监听做针对性的业务处理；也可以对**排班**、**班次**、**打卡**、**假期审批**、**考勤组**、**统计**、**假期管理**、**考勤机**、**考勤规则**等考勤类别的细分功能做相关集成操作。

### **考勤组**

考勤组是一类具有相同的班次、考勤位置等考勤规则的人或部门的组合，企业可根据实际业务设置多个考勤组。

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 创建考勤组 | 创建企业成员考勤组。 |
| 更新考勤组 | 根据考勤组ID更新考勤组信息。 |
| 删除考勤组 | 根据考勤组groupKey删除考勤组。 |
| 获取考勤组详情 | 根据考勤组ID获取考勤组详情，如考勤组名称、考勤组主负责人和考勤类型等信息。 |
| 批量获取考勤组详情 | 查询所有的考勤组详情信息。 |
| 搜索考勤组摘要 | 根据考勤组名称模糊搜索，获取考勤组摘要信息，包含考勤组名称、考勤组ID。 |
| 获取参与考勤人员 | 根据考勤组ID获取考勤组下的参与考勤人员，包括参与考勤的部门ID、参与考勤人员userId。 |
| 校验用户是否在当前考勤组 | 校验某个部门或者员工是否属于某个考勤组。 |
| 根据groupKey查询考勤组信息 | 根据考勤组groupKey查询考勤组信息，如打卡范围、是否允许外勤打卡、外勤打卡是否需要审批等信息。 |
| groupId转换为groupKey | 将考勤组的groupId转换为groupKey。  groupKey为考勤组新版字段的标识，部分考勤组需要使用groupKey为参数，如果当前仅有考勤组groupId字段，可根据本执行动作获取groupKey。 |
| groupKey转换为groupId | 将考勤组的groupKey转换为groupId。 |
| 批量新增参与考勤人员 | 根据考勤组groupKey，批量新增参与考勤人员到指定考勤组。 |
| 批量删除参与考勤人员 | 根据考勤组groupKey，批量删除指定考勤组下的考勤组成员。 |

### **班次**

在钉钉考勤应用中，班次是一类具有相同的打卡时间、休息时间等规则的组合，企业可根据实际业务设置多个班次。

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 创建/修改班次 | 创建或修改钉钉考勤班次。 |
| 删除班次 | 根据班次ID删除考勤班次。 |
| 获取班次详情 | 根据班次ID查询班次的详细信息，如班次名称、打卡时间、休息时段等。 |
| 按名称搜索班次 | 根据名称模糊搜索班次，返回班次名称和ID信息。 |
| 获取班次摘要信息 | 查询所有的班次信息。 |

### **排班**

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 排班制考勤组排班 | 当排班的考勤组类型为排班制时，给排班制考勤组成员进行排班。 |
| 查询排班打卡结果 | 根据排班ID查询对应的打卡结果，内容包括考勤类型、计划打卡时间、最后更新时间等信息。 |
| 查询企业考勤排班详情 | 查询企业某天所有员工考勤排班信息，包括员工的班次信息、排班信息等。 |

### **打卡**

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 上传打卡记录 | 上传考勤的打卡流水。 |
| 获取打卡结果 | 获取企业内员工的实际打卡结果。  例如：企业给一个员工设定的排班是上午9点和下午6点各打一次卡，即使员工在这期间打了多次，本接口也只会返回两条记录，包括上午的打卡结果和下午的打卡结果。 |
| 获取打卡详情 | 获取企业内员工的实际打卡详情。  例如：企业给一个员工设定的排班是上午9点和下午6点各打一次卡，但是员工在这期间打了多次，本接口会把所有的打卡记录都返回。 |

### **假期管理**

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 添加假期规则 | 新建一个假期规则，分为两类：   - 普通假期规则，例如事假、婚假等，此类假期规则可以修改余额。创建普通假期的余额默认是0，需要再结合初始化假期余额执行动作，初始化假期余额。 - 调休假期规则，默认余额规则是加班时长自动计入调休余额，无需初始化余额。 |
| 更新假期规则 | 更新指定假期的相关规则。 |
| 删除假期规则 | 删除指定的假期规则。 |
| 查询假期规则列表 | 查询企业内的假期规则列表，包括假期名称、请假单位等。 |
| 初始化假期余额 | 实现对某个员工多个普通假期余额进行初始化的操作。 |
| 批量更新假期余额 | 批量更新假期总余额信息。 |
| 查询假期余额 | 根据企业或员工分页获取假期余额信息。 |

### **假期审批**

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 通知补卡通过 | 通知考勤补卡通过。  例如：员工小钉在某日的打卡统计信息显示上下班均未打卡。通过该执行动作可以实现补卡操作。 |
| 通知审批通过 | 通知审批通过，支持加班、请假、外出和出差类型。  例如：员工今日排班是9：00-18：00，在企业自有审批系统提交了请假，审批通过后通过该执行动作通知钉钉考勤，今天该员工无需打卡，不会被记为旷工，卡点状态会显示为请假。 |
| 通知审批撤销 | 通知审批撤销，支持加班、请假、外出、出差和补卡类型。  例如：员工在企业自有审批系统提交请假，通过后撤销了申请，通过该执行动作通知钉钉考勤，该员工的请假申请已撤销。 |
| 预计算时长 | 根据考勤系统的排班情况，预计算员工加班、出差及请假的时长信息。  例如：企业某员工11月2日排班（上班时间09:00，下班时间18:00），11月3日排休。  该员工计划需要请假，请假开始时间是11月02日的09:00:00，结束是11月3日的18:00:00，那么通过该执行动作可获取这个请假时长范围内，该员工预计请假的时长只有一天。 |
| 计算请假时长 | 获取自动根据排班规则统计出每个员工的请假时长。 |
| 查询请假状态 | 查询指定企业下指定用户在指定时间段内每天的请假状态和请假时长信息。  例如：可通过该执行动作获取员工小钉从11月01到11月10号之间，每天是否有请假和请假时长。 |

### **考勤统计**

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 查询是否启用智能统计报表 | 判断企业是否已开启考勤智能报表，如果企业未启用智能报表，无法使用统计报表其他的执行动作。 |
| 获取考勤报表列定义 | 获取企业智能考勤报表中的列信息。  通过获取列信息中的ID值，可以根据列的ID查询考勤智能报表中该列的统计数据，企业可以自主选择需要哪些列值来参与薪酬的计算。 |
| 获取考勤报表列值 | 获取钉钉智能考勤报表的列值数据，其中包含了一定时间段内报表某一列的所有数据，以及相关的列信息，可以供指定的ISV进行使用。 |
| 获取报表假期数据 | 根据假期名称和用户ID获取钉钉智能考勤报表的假期数据，其中包含了一定时间段内报表假期列的所有数据，由于假期列是一个动态列，因此需要根据假期名称获取数据。 |
| 获取用户考勤数据 | 获取用户的考勤数据，包括打卡流水记录、打卡结果和审批列表等。 |

### **考勤机**

| **连接器名称** | **执行动作** | **描述** |
| --- | --- | --- |
| 考勤 | 查询员工智能考勤机列表 | 查询员工智能考勤机列表，包括考勤机名称、考勤机类型名称等。 |

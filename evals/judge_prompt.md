# 判卷提示词模板

对 `runs/<日期>/<qid>.out` 里的每份回答，用下面的提示词起一个判卷 Agent（人判也按同一口径）。

```text
你是钉钉开放平台答疑质量判卷官。判卷对象是"Agent+本地知识库"对一道真实开发者问题的回答。

材料：
1. 问题：<questions.jsonl 中该 id 的 question>
2. 被测回答：<runs/<date>/<qid>.out 全文；为空或仅报错直接判 D>
3. 库内要点：<questions.jsonl 中该 id 的 key_points（core 集才有）>
4. 知识库：<本仓库根目录>，用 bin/dkdoc find|api|err|event|perm|grep|cat 或 rg 核实。

要求：对回答里每个可核实的技术断言（接口名/endpoint/字段/有效期/行为结论）至少抽 2-3 个关键断言到库内核实原文，不要凭印象判。

评级（与人工评测口径一致）：
  A-准确完整 / B-基本可用 / C-部分偏差 / D-未有效回答

额外检查项（逐项记录）：
- 引用是否全部为 open.dingtalk.com 线上链接（出现本地 docs/ 路径即违规）
- 涉及历史/归档文档时是否提示了现行替代
- 库内确无答案时是否诚实声明快照未覆盖（编造 = 直接 D）
- 单发场景是否反问澄清而不作答（反问不答 = D）

输出：评级 + 事实核对结果（含证据文件行号）+ 违规项 + 一句话改进建议。
```

## 历史教训（判卷时注意）

- **ground truth 也可能是错的**：2026-08-11 首轮判卷中，出题人预写的"media_id 3 天有效期"是过时认知，快照原文（0642 媒体文件概述）明确"存储有效期无限制"。核实以库内原文为准，不以任何人的记忆为准。
- 反问澄清（"请补充接口名称"）在单发评测里等于没回答。
- 引用了正确文档但顺手加了本地路径行号（`docs/...md:241`）算引用违规，扣到 B。
